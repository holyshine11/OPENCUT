# 자동 컷 편집 구현 계획

작성일 2026-10-20. CapCut의 "무음 제거"와 "필러 단어 제거"를 출발점으로 삼되, CapCut이 약한 지점을 노린다.

CapCut은 음량 기준선 하나로 조용한 곳을 잘라 바로 적용한다. 그래서 세 가지 문제가 생긴다. 지글지글 끓는 소리처럼 말은 없지만 살려야 하는 장면까지 잘리고, 말끝 자음이나 숨이 잘려 컷이 툭툭 끊기며, 무엇이 잘렸는지 적용한 뒤에야 알 수 있다. 이 계획은 아래 네 가지로 그보다 낫게 만든다.

- 잘라도 되는 무음과 살려야 하는 장면 소리를 구분한다.
- 컷 위치를 단어 경계 안에서 가장 조용한 프레임에 맞춘다.
- 적용 전에 제안 목록과 타임라인 표시로 검토하고, 잘린 상태로 미리 재생해 본다.
- NG 후 다시 말한 문장(리테이크)을 찾아 앞의 실패 테이크를 제안한다.

## 1. 기존 코드에서 그대로 쓰는 것

- **VAD + Whisper 엔진** (`services/transcription/engine.ts`): 자동 자막을 만들 때 이미 Silero VAD로 말소리 확률을 512샘플(16kHz 기준 32ms)마다 계산하고, Whisper로 단어 단위 시간을 받는다. 자동 컷은 이 결과를 다시 쓴다. 모델을 새로 들이지 않는다.
- **말소리 구간 계산** (`transcription/speech-regions.ts` `detectSpeechRegions`): 확률 배열을 구간으로 바꾸는 순수 함수. 자동 컷용 임계값으로 한 번 더 부른다.
- **파형 요약** (`media/waveform-summary.ts`): 소스별 RMS·피크를 이미 캐시한다. 무음 구간 안에서 가장 조용한 지점을 찾을 때 쓴다.
- **분할과 리플** (`commands/timeline/element/split-elements.ts`, `ripple/apply.ts`): 자른 자리의 페이드·전환 정리까지 이미 처리한다. 컷 적용은 이 둘을 묶은 명령 하나로 만든다.
- **오디오 크로스페이드** (`timeline/audio-fade.ts`): 컷마다 10~20ms 크로스페이드를 걸어 딸깍 소리를 없앤다.
- **자막 그룹과 `wordStarts`** (`subtitles/`, `timeline/types.ts`): 자막이 단어별 시작 시각을 들고 있어서, 컷이 자막 중간을 지나가도 단어 단위로 잘라 맞출 수 있다.
- **자막 목록 패널** (4단계에서 만든 것): 리테이크 검토와 텍스트 기반 편집의 화면으로 쓴다.

## 2. 분석 결과 저장

자동 자막은 타임라인 전체를 섞은 오디오(배경음악 포함)로 인식하므로 그 VAD 결과는 자동 컷에 쓸 수 없다. 자동 컷은 미디어 원본 오디오 하나만 따로 분석한다(`autocut/analysis.ts` `getSpeechAnalysis`). VAD만 올리고 Whisper는 올리지 않는다(`analyze-speech` worker 메시지). 결과는 미디어 id별로 메모리에 캐시한다. 8분 31초 영상 분석이 CPU로 약 1초라 디스크 캐시는 두지 않는다. Whisper는 필러·리테이크 기능을 켤 때만 돌린다.

## 3. 컷 제안 엔진 (`autocut/` 순수 함수)

입력은 말소리 확률, 단어 목록, RMS, 클립의 trim 범위다. 출력은 제안 목록이다.

```ts
interface CutProposal {
	id: string;
	start: number;        // 소스 시간(초)
	end: number;
	reason: CutReason;
	confidence: number;   // 0~1, 목록 정렬과 기본 체크 여부에 쓴다
	enabled: boolean;     // 사용자가 끄고 켠다
	label?: string;       // 리테이크·필러일 때 해당 문장
}

/** 문자열 유니언으로 둔다(enum 금지 규칙) */
type CutReason = "silence" | "filler" | "retake";
```

### 3-1. 무음 분류

말이 없는 구간을 모두 자르지 않는다. 구간마다 두 값을 본다.

| 말소리 확률 | RMS | 판정 |
|---|---|---|
| 낮음 | 낮음 | 죽은 시간. 자른다 |
| 낮음 | 높음 | 끓는 소리, 칼질 같은 장면 소리. 남긴다(설정으로 켤 수 있음) |

같은 영상에 배경음악 트랙이 따로 있으면 RMS는 그 클립 자신의 오디오로만 잰다. 영상 원본 오디오에 음악이 섞여 들어간 경우는 장면 소리로 판정돼 안 잘리는 쪽으로 틀린다. 덜 자르는 실수는 사용자가 바로 보고 고칠 수 있지만 잘못 자른 건 놓치기 쉬워서 이 방향이 맞다.

### 3-2. 컷 위치 다듬기

무음 구간 양 끝을 그대로 자르면 말끝이 잘린다. 순서는 이렇다.

1. 앞 단어의 `end`와 다음 단어의 `start` 사이로 범위를 좁힌다. 단어 시간이 없으면 VAD 경계를 쓴다.
2. 앞쪽 여유(말끝 잔향)는 길게, 뒤쪽 여유(숨 들이쉬기 직전)는 짧게 남긴다. 값은 설정 파일에 둔다.
3. 남은 범위의 양 끝을 RMS가 가장 낮은 프레임으로 옮긴다. 프레임 경계에 맞춰 반올림한다.

### 3-3. 필러

Whisper large-v3-turbo는 "어", "음" 같은 말을 받아쓰지 않고 빼 버리는 경향이 있다. 그래서 단어 목록만 보면 필러를 못 찾는다. VAD로는 말소리인데 어떤 단어 시간과도 겹치지 않는 짧은 구간(0.2~1초)을 필러 후보로 잡는다. 받아쓰기에 실제로 나온 필러 단어 목록(어, 음, 그, 저기 등)은 설정 파일로 관리하고, 둘 다 해당하면 신뢰도를 올린다.

### 3-4. 리테이크

연속한 두 문장(자막 세그먼트)의 글자 유사도를 잰다. 뒤 문장이 앞 문장과 많이 겹치고(정규화한 글자 기준 편집 거리), 둘 사이 간격이 짧으면 앞 문장을 실패 테이크로 제안한다. 앞 문장이 중간에 끊긴 경우(뒤 문장의 앞부분과만 일치)도 같은 규칙으로 잡힌다. 리테이크는 오탐 비용이 커서 기본으로 체크하지 않는다.

## 4. 검토 화면

CapCut과 가장 크게 다른 부분이다.

- **패널**: 왼쪽 패널에 "자동 컷" 탭을 둔다. 맨 위에 "타이트함" 슬라이더 하나(느슨 ↔ 빡빡)와 무음·필러·리테이크 켜기 체크박스, 그 아래에 제안 목록을 둔다. 슬라이더는 최소 무음 길이와 여유 길이를 함께 움직인다. 다른 슬라이더처럼 ⌘클릭으로 기본값으로 돌아간다.
- **타임라인 표시**: 제안 구간을 클립 위에 빗금으로 그린다. 켜진 제안은 빨강, 꺼진 제안은 회색이다. 빗금을 클릭하면 켜고 끈다. 경계를 끌어 범위를 고칠 수 있다.
- **건너뛰기 미리 재생**: 적용 전에도 켜진 구간을 건너뛰며 재생한다. `playback-manager`에 건너뛸 구간 목록을 넘기는 방식이라 타임라인은 건드리지 않는다.
- **목록 항목**: 클릭하면 컷 앞 1초부터 재생한다. 리테이크와 필러 항목에는 해당 문장을 보여 준다.
- **적용**: "N개 적용" 버튼 하나. 실행 취소 한 번으로 전부 되돌아간다.

제안 상태는 프로젝트에 저장하지 않는다. 패널을 닫았다 열면 다시 계산한다(분석 결과는 캐시돼 있어 즉시 나온다).

## 5. 적용 명령 (`commands/timeline/autocut/apply-cuts.ts`)

1. 켜진 제안을 소스 시간에서 타임라인 시간으로 바꾼다. 클립의 `trimStart`와 속도 조절(`retime`)을 반영한다.
2. 뒤에서부터 각 컷의 양 끝에서 대상 클립을 나누고 가운데 조각을 지운다. 분리된 원본 오디오 트랙(`audio-separation`)이 있으면 같이 자른다.
3. 리플: 컷 길이만큼 뒤쪽 요소를 당긴다. 대상은 자른 클립의 트랙, 분리 오디오 트랙, 자막 그룹이다. 배경음악 트랙은 당기지 않는다. 음악이 컷 때문에 끊기면 안 되기 때문이다. 이 규칙이 맞지 않는 경우(음악도 같이 줄이고 싶을 때)는 써 보고 나서 옵션으로 넣는다.
4. 자막: 컷에 완전히 들어간 자막은 지우고, 걸친 자막은 `wordStarts`로 잘린 단어를 빼고 시간을 다시 맞춘다.
5. 각 컷 자리에 짧은 오디오 크로스페이드를 건다.

전부 명령 하나 안에서 처리해 실행 취소가 한 번에 된다.

## 6. 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 (완료 2026-10-20) | VAD 결과 반환·캐시, 무음 분류, 컷 위치 다듬기 (순수 함수 + 테스트) | `__tests__`에서 단어 중간을 자르는 제안이 0건 |
| 2 (완료 2026-10-20, 10절) | 검토 패널, 타임라인 빗금, 건너뛰기 재생 | 감자탕 영상에서 적용 전 미리 재생으로 결과를 확인할 수 있다 |
| 3 (먼저 진행, 2026-10-20) | 적용 명령 (분할·리플·자막 보정·크로스페이드) | 적용 후 자막이 말과 어긋나지 않고, 실행 취소 한 번에 원래대로 |

3단계를 2단계보다 먼저 했다. 영상 클립을 선택하고 속성 패널의 가위 탭(자동 컷)에서 "무음 자동 컷"을 누르면 바로 잘린다(`autocut/components/autocut-tab.tsx`, `AutocutCommand`). 검토 화면 없이 ⌘Z로 되돌린다. 적용 뒤에도 원래 클립의 첫 조각이 선택된 채로 남아 패널이 닫히지 않는다.

- 컷 자리마다 왼쪽 조각에 `crossfade` 0.02초(`autocut/settings.json` `apply.crossfadeSeconds`)를 건다. 기존 크로스페이드 모델이 잘라 낸 무음을 핸들로 끌어와 겹치므로 딸깍 소리가 없다.
- 타임라인에 자막이 있으면 그 단어 시각(`subtitleWordOffsets`)을 소스 시간으로 옮겨 VAD 결과와 합친다(`collectSubtitleWords`). 자막이 붙은 말은 VAD가 놓쳐도 자르지 않는다.
- 자막·스티커·도형·효과처럼 원본이 없는 요소는 나누지 않고 줄인다. 나누면 같은 글이 두 개가 되기 때문이다. 자막 단어 시각은 잘린 단어를 빼고 뒤 단어를 당긴다. 키프레임이 있는 요소는 뒤쪽 키프레임 시각을 지키려고 나눈다.
- 자막 인식을 취소해 worker가 죽으면 기다리던 자동 컷 분석도 실패로 끝낸다. 분석용 오디오는 worker에 복사하지 않고 넘긴다.

같은 원본으로 측정 스크립트와 앱의 컷 개수가 조금 다르다(8개 5.2초 / 10개 5.9초). 디코더가 달라서(ffmpeg / WebCodecs+리샘플) 음량이 미세하게 다르기 때문이고, 둘 다 말을 자르지는 않는다.
| 4 | 필러 감지 | 롱폼 샘플에서 사람이 고른 필러의 절반 이상을 찾고, 오탐이 목록의 20% 이하 |
| 5 | 리테이크 감지 | 리테이크가 있는 샘플에서 실패 테이크를 찾는다 |
| 6 | 텍스트 기반 편집: 자막 목록에서 단어를 지우면 영상도 잘린다 | 자막 목록만 보고 컷 편집을 끝낼 수 있다 |

1~3단계가 CapCut 무음 제거와 같은 범위이고 여기서 이미 더 낫다. 4단계부터가 CapCut에 없거나 약한 기능이다.

## 7. 설정과 측정

- 임계값(최소 무음 길이, 앞뒤 여유, RMS 기준, 필러 길이 범위, 리테이크 유사도, 필러 단어 목록, 크로스페이드 길이)은 `transcription/settings.json` 옆에 `autocut/settings.json`으로 둔다. 코드에 숫자를 쓰지 않는다.
- 측정: `~/opencut-samples/long1`과 감자탕 영상을 사람이 직접 컷 편집한 결과(남긴 구간 목록)를 정답으로 두고, 자동 컷과 겹치는 비율을 잰다. 정답 컷 목록은 사용자가 만들어 줘야 한다. 측정 스크립트는 `scripts/stt-bench.ts`처럼 `engine.ts`를 CPU로 돌린다.

## 8. 하지 않는 것 (나중에 필요하면)

- 점프컷 보정(컷마다 105~110% 확대를 번갈아 걸기): 말하는 얼굴 위주 영상에서 필요해지면 추가한다. 키프레임 기능으로 구현할 수 있다.
- 장면 전환 감지로 B롤 자동 분할: 프레임 차이 계산이 필요하다. 요리 영상에서 원하는 장면이 생기면 다룬다.
- 배경음악 비트에 컷 맞추기.
- 화면 움직임으로 장면 소리 판정 보강: RMS만으로 틀리는 사례가 나오면 추가한다.

## 9. 편집점: 말 + 화면 움직임 (쪼개기만, 2026-10-21)

고정 카메라 요리 영상(test.mp4, 2분 49초)은 인덕션 소음 때문에 바닥 음량이 -31dB라 무음이 0곳이다. 그래서 말과 화면 움직임으로 클립을 나눌 지점을 찾는다(`autocut/edit-points.ts` `proposeEditPoints`). 자를지 빠르게 넘길지는 정하지 않는다. 유지·컷·배속 토글을 써 보니 판단은 사람이 하는 편이 낫고, 촘촘히 쪼개 두는 쪽이 편집에 더 쓸모 있었다.

- 움직임: 초당 2장, 가로 160px로 디코딩해 앞 장과의 평균 밝기 차이를 잰다(`frameDifference`). 브라우저는 mediabunny `CanvasSink`(`analysis.ts` `getMotionAnalysis`), 벤치는 ffmpeg로 같은 함수를 쓴다. test.mp4에서 멈춘 화면 0.5~2.7, 끓이기·젓기 4~15, 재료 넣기 10~30이라 기준값은 3(`motion.staticBelow`), 손이 들어오는 순간은 12(`editPoints.eventAbove`).
- 지점 규칙(`settings.json` `editPoints`): 말 한 마디(0.6초보다 짧은 쉼은 한 마디, 0.3초보다 짧은 말은 무시)마다 시작 0.3초 앞 `speechStart`과 끝 0.5초 뒤 `speechEnd`. 여유는 이웃 말과의 쉼 절반을 넘지 않는다. 말 없는 구간에서 1.5초 넘게 이어지는 멈춤·움직임이 바뀌는 곳 `motionStop`·`motionStart`, 움직임이 12를 넘어서는 순간 `event`. 지점 사이가 1초보다 짧으면 말 경계를 남기고, 같은 종류면 가운데 한 점으로 합친다. 양 끝 1초 안쪽은 버린다.
- 결과: 벤치(자막 없음, VAD만)에서 51곳, 앱(자막 단어 포함)에서 35곳. 말 경계가 대부분이고 말 없는 구간은 3~4초마다 손이 들어오는 `event`로 나뉜다. 분석은 말소리 0.4초, 움직임 2.6초.
- 아직 못 하는 것: 말 더듬은 구간("매술, 마술") 같은 리테이크와 잡담 NG 판단은 사람이 자막 목록을 보고 한다(13절). VAD는 소음 속 짧은 말("꿀", "고춧가루")을 놓치므로 자동 자막을 먼저 만든 뒤 편집점을 찾아야 정확하다.

## 10. 편집점 목록과 쪼개기 (2026-10-21)

- 목록: 자동 컷 탭에 지점마다 한 줄. 체크박스(끄면 그 자리는 안 나눔), 시간(클릭하면 1초 앞부터 재생), 이유. 맨 아래 "N곳에서 쪼개기"와 "목록 지우기". 상태는 `autocut/review-store.ts`(zustand, 저장 안 함).
- 타임라인: 클립 위에 지점마다 빨간 세로선, 끈 지점은 점선(`components/review-overlay.tsx`).
- 적용: `SplitAtTimesCommand`가 같은 소스의 클립(영상과 분리된 원본 오디오)을 고른 시각에서 한 번에 나눈다(`timeline/split-element.ts` `splitElementAtTimes`). 조각 이름은 그대로, 첫 조각이 원래 id를 지켜 선택이 유지되고 ⌘Z 한 번에 돌아간다. 지우거나 당기지 않으므로 자막·배경음악은 건드리지 않는다.
- 확인(앱, test.mp4): 35곳 중 1곳을 끄고 쪼개니 조각 35개, ⌘Z로 원래 한 클립.
- 뺀 것: 유지·컷·2~5배 토글, 배속 적용(`retime` 걸기), 적용 후 길이 미리 보기, 빗금 표시. 무음 자동 컷 버튼은 그대로 두었다(검토 없이 바로 잘라 낸다).

## 11. 용어 사전 (3단계, 완료 2026-10-20)

- 배우기: 자막 목록에서 자동 자막(단어 시각이 있는 것)을 고치면 바뀐 낱말을 쌍으로 저장한다(`transcription/correction.ts` `extractCorrections`, `corrections-store.ts`, 브라우저 저장소 `transcription-corrections`). 같이 바뀐 끝 글자 하나(조사)는 뗀다("남궁진닭은 → 안동찜닭은"은 "남궁진닭 → 안동찜닭"). 모두 바꾸기로 고친 것은 바로 믿는 횟수(`correction.trustCount`)로 저장한다. 고친 걸 되돌리면 그 쌍을 지운다. 자막 패널 "고친 단어"에서 보고 지울 수 있다.
- 고치기: 다음 자동 자막부터 단어 앞부분이 배운 말과 같으면 바꾸고 뒤(조사·문장부호)는 남긴다(`correctSegments`). 2번 이상 고친 쌍은 늘, 1번 고친 쌍은 앞뒤 3초 안에 분량·동작 말(`correction.contextWords`)이 있을 때만 바꾼다. 배우지 않은 말은 건드리지 않으므로 "술맛 아니고요 맛술입니다" 같은 말장난은 그대로다.
- 앱 확인: test.mp4 자동 자막에서 "미원 반큰술"을 "미림"으로 한 번 고친 뒤 다시 받아쓰니 21줄이 그대로 나오고 "미원?"·"미원 반큰술" 두 줄이 "미림"으로 바뀌었다.
- Whisper 프롬프트 힌트에는 넘기지 않는다. 같은 영상 10초 조각에서 프롬프트를 " 미림" 한 단어로 주면 "멸치액젓? 2큰술? 응, 2큰술"이 "2큰술"만 남았고, "미림."은 "미원."을 수십 번 되풀이했고, 문장형 프롬프트는 "미림 반 큰술"을 맞히는 대신 다른 말을 빼먹고 없는 말을 지어냈다. 앱 전체 받아쓰기도 " 미림" 힌트 하나로 21줄이 13줄로 줄었다. 기존 "이름과 용어" 입력란도 같은 프롬프트를 쓰므로 같은 위험이 있다.
- 하지 않은 것: 자모 유사도로 비슷한 말을 찾아 고치기는 뺐다. test.mp4의 실제 오인식(미혼·미원→미림, 남궁진닭→안동찜닭)은 거리가 멀어 못 잡고, "미리 넣어"를 "미림"으로 바꾸는 오교정만 생긴다. 기본 요리 사전(재료·조미료 목록)은 출처를 정해야 해서 넣지 않았다. 미리보기 화면에서 글자를 직접 고친 것은 아직 배우지 않는다.

## 12. 오프라인 모델 번들 (4단계, 완료 2026-10-20)

- 읽는 곳: 모델은 `apps/web/public/models/<huggingFaceId>/…`, onnxruntime wasm은 `public/ort/`에서만 읽는다(`transcription/settings.json` `local`). `engine.ts`가 `allowRemoteModels=false`로 Hugging Face를 끊고, `worker.ts`가 origin을 붙인 절대 경로를 넣는다. Turbopack이 만든 worker는 blob: URL에서 돌아 "/models/" 같은 경로를 혼자 못 풀기 때문이다. 앱 폴더가 곧 저장소라 브라우저 Cache Storage에는 복사하지 않는다(`useBrowserCache=false`).
- 받기: `bun run models`(`scripts/fetch-models.ts`)가 설정에서 파일 목록을 만들어 받는다. Whisper large-v3-turbo fp16 인코더 1.27GB·디코더 344MB·설정 5개, Silero VAD 2.2MB, ORT wasm 21MB로 모두 1.5GB. 이미 있는 파일은 건너뛴다. `public/models/`·`public/ort/`는 git에 넣지 않는다.
- 전에는 ORT wasm을 jsdelivr CDN에서 받았다(transformers.js 기본값). 모델만 로컬에 두면 처음 돌릴 때 여기서 막힌다.
- 확인(내 맥북, 2026-10-20): Wi-Fi를 끄고(`navigator.onLine` false, huggingface.co 응답 없음) Cache Storage를 비운 뒤 test.mp4 자동 자막을 돌리니 25초 만에 21줄이 나왔고 오류 없음. 벤치(`bun scripts/autocut-bench.ts <영상>`)도 같은 폴더를 쓴다.
- 와이프 맥북에서는 `public/models`·`public/ort`를 통째로 복사하거나 인터넷이 될 때 `bun run models`를 한 번 돌린다. Cloudflare 배포(`bun run deploy`)는 1.5GB 정적 파일을 올리려 해서 이 상태로는 쓸 수 없다. 로컬 전용이 목표라 손대지 않았다.

## 13. 로컬 LLM "AI 정리" (5단계, 시도 후 뺌 2026-10-20)

- 자막을 로컬 LLM(Qwen3-4B q4f16, transformers.js v4)에 보여 주고 고친 글·구간 제목·NG 줄을 제안받는 버튼을 만들어 써 봤다. 모델 2.8GB, M5에서 45초, M1 16GB는 2~3분으로 봤다.
- 결과: 오인식 교정은 "액자→액젓" 같은 것을 못 잡았고, 구간 제목·NG 셋 정도는 사람이 자막 목록을 훑는 편이 빠르고 정확했다. 그래서 기능·모델·v4 의존성을 모두 뺐다. 3단계의 배운 단어 사전과 자동 컷 검토 목록이 주력이다.
