# 텍스트 애니메이션 구현 계획

CapCut 데스크톱의 텍스트 > 애니메이션 탭을 레퍼런스로 삼는다. 텍스트 클립 하나에 인(등장), 아웃(퇴장), 반복(루프) 애니메이션을 고르고 길이나 속도를 조절한다.

## 1. CapCut은 어떻게 동작하나

캡처와 CapCut 동작을 기준으로 정리했다.

**패널 구성**
- 오른쪽 속성 패널 상단 탭: 텍스트 / 애니메이션 / 트래킹 / 텍스트에서 음성으로. 애니메이션은 텍스트 클립을 선택했을 때만 보인다.
- 애니메이션 탭 안에 세그먼트 3개: 인 / 아웃 / 반복.
- 그 아래 검색창("Typewriter 검색 중" 같은 인기 검색어 placeholder), 즐겨찾기(★)와 "모두" 칩.
- 프리셋 그리드: 첫 칸은 "없음", 나머지는 "ABC123" 샘플 글자가 그 애니메이션으로 움직이는 썸네일. 썸네일마다 즐겨찾기 별과 다운로드 버튼이 있다(다운로드는 온라인 에셋용이라 우리는 필요 없다).
- 프리셋을 고르면 그리드 아래에 길이 슬라이더가 나온다. 반복 탭에서는 길이 대신 속도(한 바퀴 주기) 슬라이더가 나온다.

**적용 규칙**
- 인과 아웃은 한 클립에 함께 걸 수 있다. 인 길이 + 아웃 길이는 클립 길이를 넘지 못하고, 한쪽을 늘리면 다른 쪽 최대치가 줄어든다.
- 반복은 클립 전체 구간에서 돌고, 인/아웃과 같이 걸린다(CapCut 데스크톱에서 확인). 인/아웃 구간에서는 두 효과가 겹쳐 적용된다.
- 인/아웃 기본 길이는 0.5초다(CapCut 데스크톱에서 확인).
- 프리셋을 고르면 프리뷰가 그 애니메이션 구간을 한 번 재생해 보여 준다. 썸네일에 마우스를 올리면 썸네일 자체가 움직인다.
- 타임라인 클립 위에 애니메이션 구간이 반투명 띠로 표시된다(인은 앞쪽, 아웃은 뒤쪽, 반복은 전체).
- 키프레임과 같이 쓸 수 있다. 애니메이션은 키프레임으로 정한 위치와 크기 위에 덧씌워진다.
- 선택 박스는 애니메이션 중에도 정지 상태 위치에 머문다.

**프리셋 종류(캡처 기준 분류)**
- 블록 단위: 텍스트 전체가 함께 움직인다. 페이드, 확대/축소, 슬라이드, 회전, 블러, 팝(튕기며 커짐).
- 글자/단어/줄 단위: 순서대로 시차를 두고 나타난다. 타자기(Typewriter), 첫 등장, 스텝 인, 함께 일어서기, 문자 하나씩.
- 셰이더 효과: 글리치 다운, 네온 팝업, 데이터 펄스, 프리즘, 빛살 경로, 나비 폭발처럼 파티클이나 색 분리를 쓰는 것. 대부분 Pro 항목이다.

## 2. 기존 코드에서 그대로 쓰는 것

- **텍스트 렌더 경로**: `services/renderer/resolve.ts` `resolveTextNode`가 프레임마다 transform, opacity, 색을 구하고 `nodes/text-node.ts` `renderTextToContext`가 Canvas2D로 그린다. 블록 단위 애니메이션은 여기서 transform과 opacity에 곱해 넣기만 하면 된다.
- **텍스처 캐시**: `compositor/frame-descriptor.ts` `collectTextNode`의 `contentHash`가 `resolved`를 포함한다. 애니메이션 구간에서만 다시 래스터라이즈되고 정지 구간은 캐시를 그대로 쓴다.
- **블러**: `effects/definitions/blur.ts`를 `effectPasses`에 끼워 넣어 블러 인/아웃을 만든다. 새 셰이더가 필요 없다.
- **익스포트**: 같은 scene builder를 쓰므로 프리뷰와 내보내기 결과가 같다.
- **전환 모델** (`transitions/index.ts`): 프리셋 id를 `as const` 배열 + 타입 가드로 두는 방식, 저장값은 그대로 두고 렌더할 때 클립 길이에 맞춰 자르는 방식을 따른다.
- **분할** (`timeline/split-element.ts`): 전환을 떼는 자리에 텍스트 애니메이션 규칙을 추가한다.
- **즐겨찾기**: `effects/adjust-favorites-store.ts`의 zustand persist 패턴.
- **썸네일 캔버스**: `effects/components/effect-preview-canvas.tsx`의 캐시 구조.
- **속성 탭**: `components/editor/panels/properties/registry.tsx` `getTextConfig`에 탭 하나를 추가한다.
- **키프레임 합성**: `resolveTransformAtTime` 결과를 기준값으로 받아 그 위에 애니메이션을 곱한다.

## 3. 데이터 모델

`TextElement`에 선택 필드 하나를 추가한다.

```ts
textAnimation?: {
	in?: { type: string; duration: number };   // 초
	out?: { type: string; duration: number };  // 초
	loop?: { type: string; period: number };   // 한 바퀴 초
};
```

- 프리셋 id는 `TEXT_ANIMATION_IN = [...] as const` 같은 상수 배열로 둔다(enum 금지 규칙).
- 기본 길이, 최소 길이, 기본 주기는 `timeline/defaults.ts`의 `DEFAULTS.text.animation`에 둔다. 슬라이더 ⌘-클릭 리셋도 이 값을 쓴다.
- 저장된 길이는 건드리지 않는다. 클립을 줄이면 렌더 시점에 인 + 아웃 ≤ 클립 길이가 되도록 비율대로 자른다. 클립을 다시 늘리면 원래 길이가 돌아온다.
- 분할: 왼쪽 조각은 `in`만, 오른쪽 조각은 `out`만 남긴다. `loop`는 양쪽 다 갖는다.
- 복제와 복사: 필드를 그대로 따라간다.
- 텍스트 스타일 프리셋(`style-presets.ts`)과 스타일 기억(`style-memory.ts`)에는 넣지 않는다. 스타일과 동작을 따로 관리하는 CapCut과 같다.

## 4. 애니메이션 엔진

`text/animation/` 아래 순수 함수로 둔다. 프레임워크 import 없이 작성해 나중에 `rust/`로 옮기기 쉽게 한다(키프레임과 전환 해석도 지금은 TS에 있어서 일단 같은 층에 둔다).

**프리셋 정의**

```ts
{
	id: "typewriter",
	unit: "block" | "grapheme" | "word" | "line",  // 문자열 유니언
	stagger: 0.6,   // 유닛 간 시차 비율 (block이면 0)
	easing: ...,    // animation/bezier.ts 재사용
	sample: (t) => ({ dx, dy, scale, rotate, opacity, blur }),  // t: 0→1
}
```

- 아웃 프리셋은 대부분 인 프리셋을 거꾸로 돌린 것이라 `reverse: true` 플래그로 만든다.
- 반복 프리셋은 `sample(phase)`에서 phase가 0→1을 주기마다 반복한다.
- 한 시점의 결과는 "유닛별 상태 배열"이다. 블록 프리셋은 길이 1짜리 배열.

**해석 순서** (`resolveTextNode` 안)
1. 키프레임으로 기준 transform과 opacity를 구한다(지금과 같음).
2. localTime으로 인, 아웃, 반복 진행도를 구한다. 클립 길이 초과분은 비율대로 자른다.
3. 블록 프리셋이면 결과를 transform과 opacity에 곱하고 블러는 effectPasses 앞에 끼운다. 반복과 인(또는 아웃)이 함께 걸린 구간은 두 결과를 차례로 곱한다(위치 이동은 더하고, 크기와 투명도는 곱한다).
4. 유닛 프리셋이면 유닛별 상태를 `resolved.unitStates`로 넘긴다.

**유닛 단위 그리기**
- `Intl.Segmenter`로 줄을 글자(grapheme)나 단어로 쪼갠다. 한글 음절, 이모지, 결합 문자가 깨지지 않는다.
- 각 유닛의 x 위치는 `measureText(line.slice(0, i))`로 앞부분 폭을 재서 구한다. 커닝이 유지된다. 측정 결과는 `measureTextElement` 캐시에 넣어 프레임마다 다시 재지 않는다.
- `drawMeasuredTextLayout`에 선택 인자 `unitStates`를 추가한다. 없으면 지금처럼 줄 단위로 그리고, 있으면 유닛마다 save/translate/scale/globalAlpha 후 stroke → fill 순서로 그린다. 그림자도 유닛마다 적용한다.
- 텍스트 배경 박스는 유닛 애니메이션 중에도 전체 크기로 그리고 블록 opacity만 따른다.
- 한계: 아랍어처럼 글자가 이어지는 문자는 글자 단위로 쪼개면 모양이 바뀐다. 그런 줄은 줄 단위로 대체한다.

**선택 박스**: `preview/element-bounds.ts`는 애니메이션을 무시한 정지 상태 크기를 쓴다.

## 5. UI

**속성 패널 "애니메이션" 탭** (`getTextConfig`에 추가)
- 인 / 아웃 / 반복 세그먼트. 이미 걸린 쪽에는 점 표시.
- 검색창(프리셋 이름, 키워드), ★ 즐겨찾기 / 모두 칩.
- 프리셋 그리드: "없음" + 프리셋 썸네일. 선택된 칸은 테두리 강조.
- 그리드 아래 슬라이더: 인/아웃은 길이(최대 = 클립 길이 − 반대쪽 길이), 반복은 속도. `Slider` + `onReset` 규칙을 따른다.
- 적용은 명령 하나로 묶어 실행 취소 한 번에 되돌아간다.
- 프리셋을 고르면 플레이헤드를 애니메이션 시작으로 옮기고 그 구간만 한 번 재생한다.
- 자막 묶음(`subtitleGroupId`)에 속한 클립이면 "자막 전체에 적용" 버튼을 둔다. CapCut 캡처에는 없지만 자동 자막 수십 개에 하나씩 거는 수고를 없앤다.

**썸네일**
- 작은 캔버스에 "가나다 ABC"를 같은 엔진, 같은 `drawMeasuredTextLayout`으로 그린다. 썸네일과 실제 결과가 어긋나지 않는다.
- 평소에는 진행도 0.6 지점 정지 화면, 마우스를 올리면 requestAnimationFrame으로 반복 재생. 정지 화면은 캐시한다.

**타임라인**
- 텍스트 클립 위에 인 구간(앞), 아웃 구간(뒤), 반복(전체)을 반투명 띠로 그린다.

## 6. 프리셋 목록 (단계별)

| 단계 | 인 | 아웃 | 반복 |
|---|---|---|---|
| 1 블록 | 페이드, 확대, 축소, 슬라이드 4방향, 회전, 블러, 팝, 바운스 | 인의 역재생 + 아래로 떨어짐 | 흔들기, 맥박, 깜빡임, 둥둥 |
| 2 유닛 | 타자기, 글자 페이드, 글자 팝업, 웨이브 인, 단어씩, 줄씩 올라오기, 랜덤 등장 | 인의 역재생, 글자 흩어지기 | 글자 웨이브, 글자 순차 점프 |
| 3 셰이더(선택) | 글리치, RGB 분리, 네온 깜빡임 | 같음 | 글리치 루프 |

3단계는 `rust/crates/compositor`에 셰이더를 추가해야 해서 wasm 재빌드와 `rust/wasm/pkg` 커밋이 따른다. 1, 2단계를 써 보고 필요하면 진행한다.

## 7. 개발 단계와 검증

1. **모델, 엔진, 블록 프리셋**: 데이터 필드, defaults, 분할 규칙, 엔진, 블록 프리셋, `resolveTextNode` 연결. 테스트: 진행도 0/1 끝값, 인 + 아웃이 클립 길이를 넘을 때 자르기, 분할 후 in/out 배분, 반복 주기.
2. **패널과 타임라인 띠**: 애니메이션 탭, 슬라이더, 프리뷰 자동 재생, 타임라인 표시.
3. **유닛 엔진과 유닛 프리셋**: 분절, 폭 측정, 유닛 그리기. 테스트: 한글/이모지/영문 분절, 정렬(좌/중/우)별 유닛 x 위치.
4. **썸네일, 즐겨찾기, 검색, 자막 전체 적용**.
5. (선택) 셰이더 프리셋.

단계마다 ego-browser로 실제 앱에서 적용 → 스크럽 → 내보내기 한 프레임 비교를 확인하고 커밋한다.

## 8. Codex(Astra) 협업 방식

- 시작 전: 이 계획서를 `ecc:astra-review`로 넘겨 빠진 부분과 아쉬운 부분을 받고 계획을 고친다.
- 단계마다: 구현 → 테스트 → `ecc:astra-review`로 변경분 교차 검토 → 지적 반영 → 커밋.
- 반영하지 않은 지적은 이유를 남겨 사용자에게 함께 보고한다.

## 9. Astra 1차 검토 반영 (2026-11-06)

계획서를 Codex Astra(gpt-6-astra)에 3라운드 넘겼다. 1차 HIGH 7건과 MEDIUM 2건, 2차 HIGH 1건(슬라이더 범위 역전), 3차 HIGH 2건(합자 깜빡임, 캐시 키)을 받았다. 모두 코드와 대조해 사실로 확인했고 아래처럼 계획을 고친다. 이 절이 앞 절과 충돌하면 이 절을 따른다.

**시간 단위 (HIGH)**
- `startTime`, `duration`, `getElementLocalTime` 결과는 틱(`TICKS_PER_SECOND` = 초당 120,000)이고 `textAnimation`의 길이와 주기는 초다. 엔진 입력은 초로 통일하고 `resolveTextNode`에서 `localTime / TICKS_PER_SECOND`로 한 번만 바꾼다. 테스트는 실제 틱 값으로 0.5초 인 진행도와 반복 주기를 확인한다.

**트림 후 슬라이더 (HIGH)**
- 저장값과 렌더용 유효값을 나눈다. 유효값 = 클립 길이에 맞춰 비율대로 줄인 값.
- 슬라이더는 유효값을 보여 준다. 최대를 먼저 구한다: 최대 = 클립 길이 − 반대쪽 유효값. 최소 = `min(DEFAULTS.text.animation.minDuration, 최대, 현재 유효값)`이라 최소가 최대를 넘는 일이 없다.
- 최대가 0 이하이거나 최소 = 최대이면 슬라이더를 비활성화하고 현재 유효값만 보여 준다.
- 테스트: 인:아웃 저장값 1:9인 클립을 최소 길이의 2배보다 짧게 트림한 뒤 양쪽 슬라이더 드래그와 리셋.
- 사용자가 슬라이더를 움직이면 인과 아웃 둘 다 유효값으로 저장해 저장값과 화면 값을 맞춘다. ⌘-클릭 리셋은 0.5초를 위 범위로 자른 값.

**커닝과 합자 (HIGH)**
- 글자 i의 x 위치는 `width(앞부분 + 글자 i) − width(글자 i)`로 구한다. 앞 글자와의 커닝 쌍이 들어간다. `letterSpacing`도 같은 식에 포함한다.
- 합자는 글자 단위로 쪼개면 보존할 수 없고, 애니메이션 끝에서 줄 단위로 돌아가면 마지막 프레임에 글리프가 바뀌어 깜빡인다. 그래서 유닛 프리셋이 걸린 클립은 클립 전체 구간(정지 구간 포함)을 같은 유닛 방식으로 그린다. 글리프가 처음부터 끝까지 같아 불연속이 없다. 대가로 그 클립은 "fi" 같은 합자가 풀린 모양으로 나온다. 한글 폰트는 합자를 거의 쓰지 않아 실사용 영향은 작다.
- 테스트: 유닛 프리셋 클립의 진행도 0.99와 1.0 사이, 그리고 정지 구간에서 한글, 영문("AV", "fi"), 이모지 픽셀 비교.
- 글자가 이어지는 문자(아랍어 등)는 유닛 프리셋에서 줄 단위로 대체한다.

**투명 채움 합성 (HIGH)**
- 지금 `drawMeasuredTextLayout`은 채움 투명도가 1보다 작고 외곽선이나 그림자가 있으면 불투명 글자를 그리고 `destination-out`으로 속을 지운 뒤 채움을 다시 그린다. 유닛 그리기도 이 3단계를 그대로 따르되, 각 단계에서 유닛마다 같은 transform을 적용한다.
- 유닛 투명도는 이 합성 안에 섞지 않는다. 투명도가 1보다 작은 유닛은 작은 임시 캔버스에 3단계를 그린 뒤 `globalAlpha`로 한 번에 얹는다. 애니메이션 구간에서만 생기는 비용이다.
- 회귀 테스트: 배경, 외곽선, 그림자, 채움 투명도 0/50/100 조합.

**자막 목록 분할 (HIGH)**
- `subtitles/list-actions.ts` `splitSubtitle`은 `split-element.ts`를 거치지 않고 요소를 통째로 복사한다. 분할 규칙(왼쪽은 in, 오른쪽은 out, loop는 양쪽)을 공통 함수 하나로 만들어 두 경로에서 함께 쓴다. 테스트도 두 경로 각각 둔다.

**프리뷰 직접 편집 (HIGH)**
- `preview/components/text-edit-overlay.tsx`는 키프레임 transform만 적용한 투명 contentEditable을 캔버스 글자 위에 얹는다. 편집 중인 텍스트 클립은 애니메이션을 끄고 정지 상태로 그린다. 편집이 끝나면 다시 켠다.

**저장 데이터 검증 (HIGH)**
- 프로젝트 로드는 `textAnimation`을 검증하지 않는다. 엔진 진입점에서 프리셋 id가 상수 배열에 있는지, 길이와 주기가 유한한 양수인지 확인한다. 아니면 그 슬롯만 없는 것으로 보고 그린다(저장값은 지우지 않는다). 주기 0으로 나머지 연산이 NaN이 되는 경우를 테스트한다.

**측정 캐시 (MEDIUM)**
- `measureTextElement`에는 결과 캐시가 없다. 캐시를 새로 만들되 유닛 배열은 캐시하지 않고 "줄의 문자열 오프셋별 앞부분 폭"만 캐시한다. 키는 폰트 문자열, 크기, 자간, 줄 텍스트. 글자, 단어, 줄 유닛 배열은 매번 분절 결과로 이 폭 표에서 조립하므로 같은 텍스트에서 글자 프리셋과 단어 프리셋을 바꿔도 어긋나지 않는다.
- `document.fonts`의 `loadingdone` 이벤트에서 비운다. 시간에 따라 바뀌는 배경 측정과 섞지 않는다.
- 테스트: 같은 텍스트에서 글자 프리셋과 단어 프리셋을 번갈아 적용.

**엔진 위치 (MEDIUM, 2026-11-06 결정: Rust)**
- 사용자 결정으로 진행도 계산, 프리셋 샘플링, 합성, 유효 길이와 슬라이더 범위, 저장값 검증은 `rust/crates/text-animation`에 둔다. 기본 길이와 최소 길이도 Rust 상수로 두고 `timeline/defaults.ts`가 wasm에서 읽는다. 웹에는 Canvas 측정과 그리기, UI, 타임라인 데이터 조작(분할)만 남는다.
- AGENTS.md는 플랫폼에 무관한 로직을 `rust/`에 두라고 한다. 진행도 계산, 프리셋 샘플링, 합성 규칙은 이 범주에 든다. Canvas 측정과 그리기, UI만 웹에 남는다.
- Rust로 가면 프리셋 수정마다 wasm 재빌드와 `rust/wasm/pkg` 커밋이 따르고, 프레임마다 유닛 상태 배열이 wasm 경계를 넘는다. 키프레임과 전환 해석은 지금 TS에 있다.

## 10. 3단계 구현 메모 (2026-11-06)

- 유닛 프리셋: 인/아웃은 타자기, 글자 페이드, 글자 팝업, 웨이브 인, 랜덤 등장, 흩어지기, 단어씩, 줄씩 올라오기. 반복은 글자 웨이브, 글자 점프. 단어/줄 프리셋은 중심이 어긋나지 않도록 이동과 투명도만 쓴다.
- 웹은 줄을 글자(공백 포함, 밑줄이 이어지게)로 쪼개고 단어/줄 번호를 넘긴다. Rust가 단위별 상태를 돌려준다. 이어지는 문자(아랍 등)의 줄은 줄째로 한 조각이다.
- 그리기 순서는 줄마다 그림자 → 불투명 조각(외곽선 → 채움) → 반투명 조각(같은 투명도끼리 묶어 임시 캔버스) 순이고 배경은 맨 아래에 깐다. 인이 끝난 정지 상태는 Chrome에서 줄 그리기와 같은 그림이다.
- 알려진 한계: 투명도가 다른 조각끼리 겹치는 자리의 앞뒤, 유닛 프리셋 클립의 합자 해제, 채움 투명도 < 1 지우기를 줄마다 하는 점(줄끼리 겹칠 때만 다름).
- `@napi-rs/canvas`는 텍스트의 destination-out 합성이 Chrome과 달라, 그 합성이 들어가는 조합은 Chrome 캔버스에서 확인한다.
