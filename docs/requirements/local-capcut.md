# 로컬 전용 캡컷형 편집기 요구사항

작성일 2026-10-19. 이 문서는 OPENCUT 포크를 집에서 쓰는 영상 편집기로 완성하기 위한 기준 문서다. 단계를 끝낼 때마다 완료 기준을 이 문서로 확인한다.

## 1. 전제

- 사용자: 아내. M1 맥북(RAM 16GB)에서 숏폼(9:16)과 롱폼(16:9)을 같은 비율로 만든다. 영상 10개를 만들면 5개씩이다.
- 촬영 소스: 갤럭시 폰. 대부분 1080p이고 4K는 드물다.
- 실행 형태: 브라우저로 여는 로컬 웹앱(`localhost`). 데스크톱 앱 래핑은 하지 않는다.
- 개발은 개발자 맥북에서 하고, 아내 맥북에서는 사용만 한다.
- 원본 OpenCut 저장소는 archived 상태다. 상위 저장소와의 병합은 신경 쓰지 않는다.
- 성능 기준선: 1080p, 최대 20분 영상에서 미리보기가 끊기지 않는다.

## 2. 범위 밖

다음은 이번 작업에서 하지 않는다. 필요해지면 별도 문서로 다룬다.

- 전환 효과, 필터·LUT, 크로마키, 텍스트 등장·퇴장 애니메이션 같은 효과류 전체
- 목소리·배경음 분리(ML 소스 분리). 현재 `timeline/audio-separation/`은 오디오를 별도 트랙으로 떼어 낼 뿐 분리 모델이 아니다.
- 단어 단위 카라오케 강조 자막
- 자막 번역(한국어 음성 → 영어 자막)
- 내장 스타일 프리셋
- 프리셋 가져오기·내보내기
- 4K 프록시. 실제로 버벅임이 측정될 때만 추가한다.

## 3. 단계별 요구사항

### 1단계. 로컬 전용 실행 환경

- better-auth, Postgres, Upstash Redis, Marble 블로그, Freesound 음원 검색을 제거한다. `env/web.ts`에서 필수 환경 변수가 사라져야 한다.
- 랜딩, 블로그, 로드맵 같은 홍보용 페이지를 지운다. `/`로 들어가면 프로젝트 목록이 열린다.
- 배경음악은 맥에 있는 파일을 가져오는 방식만 남긴다.
- `start-mac.command`는 실행할 때마다 `git pull`로 최신 버전을 받고, 바뀐 것이 있으면 다시 빌드한 뒤 브라우저를 연다.
- `git pull`이 실패하면(오프라인, 충돌 등) "업데이트 실패, 기존 버전으로 실행합니다"라는 안내를 띄우고 기존 버전으로 실행한다. 사용이 막히면 안 된다.
- 앱을 처음 열 때 `navigator.storage.persist()`로 영구 저장을 요청한다.

완료 기준: 환경 변수 파일 없이 새로 받은 저장소에서 `start-mac.command`를 더블클릭하면 프로젝트 목록이 열린다. 네트워크를 끊어도 기존 버전으로 실행된다.

### 2단계. 한글 폰트와 스타일 유지

- 아래 OFL 폰트를 앱 안에 포함해서 인터넷 없이 쓸 수 있게 한다. 재배포 조건이 따로 있는 폰트(배민체, G마켓 산스 등)는 넣지 않는다. 이런 폰트는 맥에 설치하면 기존 "설치된 폰트 선택" 기능으로 쓸 수 있다.
  - 본문: Pretendard, Noto Sans KR, 나눔고딕, 나눔스퀘어라운드, 고운돋움
  - 강조: Black Han Sans, Do Hyeon, Jua
  - 손글씨: 나눔손글씨 펜
- 텍스트 테두리(색, 두께)를 추가한다. 원래 계획에 없었지만, 스타일 기억 항목에 테두리가 들어 있는데 기능 자체가 없어서 이 단계에서 넣었다.
- 자동 자막 기본 스타일을 Arial에서 Pretendard Bold + 검은 테두리로 바꾼다. 현재 기본값은 `subtitles/build-subtitle-text-element.ts`의 `resolveSubtitleStyle`에 하드코딩돼 있다.
- 마지막으로 쓴 텍스트 스타일을 기억해서 새 텍스트와 자동 생성 자막에 기본으로 적용한다. 모든 프로젝트에 공통이다. 스타일 항목은 폰트, 크기, 색, 테두리, 배경 박스, 그림자(5단계 이후), 위치다.
- `⌘⌥C`로 스타일만 복사하고 `⌘⌥V`로 스타일만 붙여 넣는다. 여러 텍스트를 선택한 상태에서 붙여 넣으면 한꺼번에 적용된다.
- 요소 전체 복사·붙여넣기 시 스타일이 유지되는 동작은 이미 있다(`commands/timeline/clipboard/paste.ts`). 깨지지 않게 유지만 한다.

완료 기준: 자막 하나의 스타일을 바꾼 뒤 자동 자막을 새로 생성하면 같은 스타일로 나온다. 다른 프로젝트를 열어도 마찬가지다.

### 3단계. 음성 인식 정확도 1단계

현재 상태(`services/transcription/worker.ts`): 모든 모델이 `q4` 압축이고 기본 모델은 `whisper-small`이다. 단어 단위 시간 정보, VAD, 환각 필터, initial prompt가 없다. 인식 중 진행률이 표시되지 않고, 취소 버튼이 실행 중인 인식을 멈추지 못한다. 언어 목록에 한국어가 없다.

- 기본 모델을 `whisper-large-v3-turbo`로 바꾸고 압축 수준을 fp16 또는 q8로 올린다. 어느 쪽을 쓸지는 샘플 측정으로 정한다.
- 인식 언어 기본값은 한국어로 고정한다. 영어를 선택할 수 있고, 자동 감지는 기본으로 쓰지 않는다.
- VAD로 무음 구간을 빼고 인식한다. 무음에서 "시청해 주셔서 감사합니다" 같은 문장이 지어지는 것을 막는 게 목적이다.
- 같은 문장이 반복되거나 알려진 환각 문구가 나오면 걸러 낸다. 환각 문구 목록은 코드가 아니라 설정 파일로 관리한다.
- 용어 사전: 사용자가 이름, 상호, 고유명사를 등록하면 인식할 때 힌트로 넘긴다. 사전은 모든 프로젝트 공통이다.
- 단어 단위 시간 정보를 받아 4단계 줄 나누기에 쓴다.
- 인식 중 진행률을 표시하고, 취소하면 실제로 멈춘다.
- Whisper 모델은 처음 쓸 때 한 번 내려받고, 그 뒤로는 오프라인으로 동작한다.

정확도 측정:

- 샘플: `~/opencut-samples/`에 숏폼 2개(`short1`, `short2`), 롱폼 1개(`long1`)와 각각의 정답 `.srt`. 롱폼은 1개만 있다. 저장소에는 커밋하지 않는다. 정답은 영상에 입혀진 자막을 OCR로 읽은 초안(`*.draft.srt`)을 사람이 실제 발화에 맞게 고쳐서 만든다.
- 지표: 문자 오류율(CER). 띄어쓰기와 문장부호를 뺀 글자 기준으로 잰다.
- 목표: CER 10% 이하, 10분 영상 처리 5분 이내.

측정 방법: `bun scripts/stt-bench.ts ~/opencut-samples <모델 폴더> [fp16|q8] [용어 파일]` (`apps/web`에서 실행). 브라우저와 같은 `services/transcription/engine.ts`를 CPU로 돌린다.

2026-10-19 중간 측정 (개발자 맥북, OCR 초안 기준이라 잠정치):

| 샘플 | 새 엔진 q8 | whisper.cpp turbo q8 | 처리 시간 (브라우저 WebGPU fp16) |
|---|---|---|---|
| short1 (41초) | 21.5% | 25.1% | 약 6초 |
| short2 (44초) | 23.0% | 21.9% | 약 6초 |
| long1 (8분 31초) | 10.4% | 9.6% | 65초 |

- 두 엔진의 정확도가 거의 같아서 whisper.cpp로 바꿀 이유는 아직 없다.
- 숏폼 수치에는 초안의 문제가 섞여 있다. 자막에만 있고 말하지 않은 글자("250ml")와 표기 차이("3T" / "세 큰술")가 그것이다.
- 용어 사전을 넣으면 "요스→육수", "안턴→남편"처럼 고쳐지지만, 비슷한 소리를 사전 단어로 끌어가는 부작용도 있다("돼지고기→돼지국밥").
- 모델 첫 다운로드는 약 1.6GB이고 4분쯤 걸렸다. 그 뒤로는 캐시에서 3초 만에 올라온다.

완료 기준: 사람이 고친 정답 기준으로 샘플 3개 모두에서 목표를 만족하고, 아내 맥북(M1)에서 10분 영상이 5분 안에 끝난다. 만족하지 못하거나 불확실한 단어 표시가 꼭 필요하다고 판단되면, 4단계 전에 whisper.cpp(Metal) 엔진으로 전환하는 단계를 끼워 넣는다. 전환하면 로컬 Next 서버가 whisper.cpp를 실행하고, 설치 스크립트가 실행 파일과 모델을 준비하며, 신뢰도가 낮은 단어를 자막 목록에서 강조하는 기능을 함께 넣는다.

판정 (2026-10-19): 실제 영상으로 자동 자막을 써 보니 품질이 만족스러워 3단계를 완료로 본다. 정답 SRT 검수와 M1 처리 시간 측정은 하지 않았고, 위 표가 마지막 측정이다. whisper.cpp 전환과 불확실한 단어 표시는 하지 않는다(#4, #5). 자막 품질이나 M1 속도에 문제가 생기면 그때 정답을 고쳐 다시 재고 전환 여부를 정한다.

### 4단계. 자막 목록 패널과 줄 나누기

- 자막 목록 패널: 자막 전체를 시간순 목록으로 보여 준다. 텍스트 직접 수정, 클릭하면 해당 시점으로 이동, 분할·병합, 찾아 바꾸기, 시작·끝 시간 조정을 지원한다.
- 자막은 별도 트랙 타입을 새로 만들지 않고 기존 텍스트 요소에 자막 그룹 표시를 붙여서 묶는다.
- 줄 나누기: 지금은 3단어씩 기계적으로 자른다(`transcription/caption.ts`). 이를 단어 시간 정보 기반의 글자 수 기준 분할로 바꾼다.
- 설정값은 사용자가 바꿀 수 있다. 프로젝트 비율이 9:16이면 숏폼 값, 16:9면 롱폼 값을 자동으로 고른다. 설정 화면에 "숏폼 권장 / 롱폼 권장" 버튼과 짧은 안내를 넣는다.

| 항목 | 숏폼 (9:16) | 롱폼 (16:9) |
|---|---|---|
| 줄당 최대 글자 수 | 14자 | 22자 |
| 최대 줄 수 | 1줄 | 2줄 |
| 최소 / 최대 표시 시간 | 0.6초 / 3초 | 1초 / 6초 |
| 문장부호 | 마침표·쉼표 제거 | 유지 |

완료 기준: 롱폼 샘플 하나의 자동 자막 검수(오타 수정, 분할·병합)를 타임라인을 직접 건드리지 않고 목록 패널 안에서 끝낼 수 있다.

### 5단계. 텍스트 그림자와 사용자 프리셋

- 텍스트 그림자를 추가한다(색, 투명도, 흐림, x/y 거리). 파라미터는 `params/registry.ts`의 `textElementParams`에 등록하고, 그리기는 `text/primitives.ts`에서 처리한다.
- 사용자 스타일 프리셋: 저장, 이름 변경, 삭제, 적용. 저장 항목은 2단계의 스타일 항목과 같다. 맥북 안에 저장하고 모든 프로젝트에서 공유한다.
- 내장 프리셋은 제공하지 않는다.

완료 기준: 프리셋을 저장하고 다른 프로젝트에서 여러 자막에 한꺼번에 적용할 수 있다. 앱을 다시 켜도 프리셋이 남아 있다.

### 6단계. 내보내기

- 기본 해상도는 프로젝트 비율을 따른다. 9:16은 1080×1920, 16:9는 1920×1080이다. 30fps, MP4(H.264/AAC), 고화질.
- 자막을 SRT 파일로 따로 내보낸다. 유튜브에 자막을 올릴 때 쓴다.

완료 기준: 내보낸 SRT를 다시 가져오면 원래 자막과 시간·텍스트가 같다.

### 7단계. 한국어/영어 UI

- UI 문자열 전체를 한국어와 영어로 제공한다. 기본은 한국어이고 설정에서 바꾼다.

완료 기준: 한국어 모드에서 영어로 남은 UI 문자열이 없다.

### 8단계. 프로젝트 백업·복원

- 프로젝트 하나를 미디어까지 포함한 `.zip` 파일로 내보내고, 다시 불러온다.

완료 기준: 개발자 맥북에서 백업한 프로젝트를 아내 맥북에서 복원하면 편집 상태가 그대로 나온다.

## 4. 확인된 위험

- 갤럭시 HEVC 영상은 브라우저의 WebCodecs가 디코딩을 지원할 때만 열린다. 지원하지 않으면 지금처럼 H.264로 변환하라는 안내가 뜬다(`media/processing.ts`).
- 브라우저 저장소에 있는 프로젝트는 브라우저 데이터를 지우면 사라진다. 1단계의 영구 저장 요청과 8단계의 백업으로 줄인다.
- `large-v3-turbo` 모델은 용량이 커서 처음 내려받을 때 시간이 걸린다. 다운로드 진행률은 이미 표시된다.
