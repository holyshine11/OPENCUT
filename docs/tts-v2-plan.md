# 송이·송강 TTS 2세대 계획

작성일 2026-11-21. 1세대(GPT-SoVITS v2ProPlus, `docs/tts-plan.md`)를 갈아엎는 계획이다. OPENCUT과 TTS 서버 사이 계약(`/voices`·`/config`·`/synth`)은 그대로 두고, 그 뒤의 엔진과 목소리 데이터를 바꾼다.

요구 사항(사용자, 2026-11-21):

- 지금 내레이션은 발음이 부정확하고 모델이 약하다. 실제 송이·송강 녹음과 거의 같게 들려야 한다.
- 이 맥북(실측: **Apple M1, 8코어 CPU·8코어 GPU, 16GB** — M1 Pro가 아니다)에서 인터넷 없이 돌아야 한다.
- 속도 기본값 1.2, 빨라져도 피치가 올라가면 안 된다.
- 새 녹음(`~/Downloads/aux/송이1~3.mp3`, `송강이1~3.m4a`, 각 3~4분)으로 학습한다. 잡음이 있으니 정제해서 쓴다.

## 1. 지금 상태 측정 (2026-11-21, 이 M1)

같은 6문장(요리 내레이션, 116음절)을 지금 서버로 합성하고, 새 녹음과 비교했다. 측정 스크립트는 세션 임시 폴더에 있다(P0에서 `apps/tts/eval/`로 옮긴다).

### 1-1. 화자 유사도 (ERes2NetV2 코사인, 높을수록 같은 사람)

| 비교 | 송이 | 송강 |
|---|---|---|
| 새 녹음 ↔ 새 녹음 (천장) | 0.980 | 0.982 |
| **새 녹음 ↔ 지금 합성** | **0.769** | **0.715** |
| 새 녹음 ↔ 예전 학습용 참조 음성 | 0.803 | 0.716 |
| 지금 합성 ↔ 예전 참조 음성 | 0.837 | 0.900 |

핵심 발견: 모델은 **예전 학습 데이터는 잘 따라 했지만(0.84·0.90), 예전 데이터 자체가 지금 녹음과 다른 소리다(0.80·0.72)**. 마이크·방·녹음 상태가 달랐다는 뜻이다. 엔진을 바꾸지 않아도 새 녹음으로 다시 학습하는 것만으로 크게 나아질 여지가 있고, 엔진을 바꾸더라도 데이터가 먼저다.

주의: ERes2NetV2는 GPT-SoVITS v2Pro가 학습에 쓰는 화자 모델이라 GPT-SoVITS 쪽에 유리하게 나올 수 있다. P0에서 독립 화자 모델(WavLM-SV 등)을 하나 더 붙인다.

### 1-2. 음높이 (F0 중앙값)

| | 송이 | 송강 |
|---|---|---|
| 새 녹음 | 211–220 Hz | 111–119 Hz |
| 지금 합성 1.0배 | 228 Hz (+0.6반음) | 138 Hz (**+2.9반음**) |
| 지금 합성 1.2배 | 225 Hz (+0.4반음) | 137 Hz (**+2.8반음**) |
| 예전 참조 음성 | 208–224 Hz | 126–140 Hz |

- **송강은 속도와 상관없이 원래 목소리보다 약 3반음 높다.** 예전 학습 데이터(126–140 Hz)가 실제 목소리(약 115 Hz)보다 높았던 것이 그대로 굳었다. "피치가 올라간다"는 체감의 주원인은 속도가 아니라 이것으로 본다.
- 1.0 → 1.2배에서 평균 음높이는 오르지 않았다(지금 엔진의 속도 처리는 토큰 반복 방식이라 음높이를 바꾸지 않는다). 다만 송이는 상단(p90)이 실제보다 높아(319 vs 297 Hz) 억양 폭이 과하다.
- 고음역(4kHz 위) 에너지: 송강 합성 -31.9dB vs 실제 -24.6dB. **송강 합성이 7dB 먹먹하다**(울림 제거 후처리와 예전 녹음 탓).

### 1-3. 발음 (Whisper small 받아쓰기 CER, 숫자 표기 차이 포함이라 절대값보다 틀린 낱말을 본다)

| | 1.0배 | 1.2배 | 틀린 곳 |
|---|---|---|---|
| 송이 | 0.074 | 0.083 | 센 불→"생불/생물", 고기는→"오기는", 펴서→"켜서", 재워 두면→"재워 주면" |
| 송강 | 0.066 | 0.091 | 식혀서→"시켜서", 센 불→"생물", 꽃잎→"꼬입" |

서버 쪽 문장별 최대 CER은 송이 1.2배 0.294였다(재생성 검사 허용치 안이라 그대로 통과). 1.2배에서 더 나빠지는 이유: 로컬 패치(`patches/gpt-sovits.patch`, `models.py`)가 25Hz 의미 토큰을 nearest로 솎아 속도를 올린다. 1.2배면 토큰 6개 중 1개가 빠지고, 토큰 하나가 40ms라 짧은 자음(ㅎ, 된소리 앞 막힘)이 통째로 사라질 수 있다.

### 1-4. 말 속도와 생성 시간

| | 조음 속도(음절/소리 난 초) |
|---|---|
| 새 녹음 (송이·송강) | 5.7–6.4, 평균 약 6.0 |
| 지금 합성 1.0배 | 5.1–5.3 |
| 지금 합성 1.2배 | 6.5–6.6 |

지금 "1.2배"는 새 녹음의 자연스러운 속도보다 약 8% 빠른 정도다. 새 시스템에서 "1.0"을 새 녹음 속도로 다시 정하면 1.2는 약 7.2음절/초로 꽤 빨라진다 — 10절 질문 3.

생성 시간(실시간 배수, 낮을수록 빠름): 송이 1.8–2.0, 송강 2.9–3.0(울림 제거 포함). 3분 내레이션에 6~9분 걸린다.

### 1-5. 새 녹음 상태

| | 송이 (mp3 44.1k 스테레오 110–130kbps) | 송강 (AAC 48k 모노 69kbps) |
|---|---|---|
| 길이 | 3 × 3분 54초 = 11.7분 | 3분 19초 + 3분 13초 + 3분 50초 = 10.4분 |
| 쉬는 구간 잡음 | 1·3번은 **완전 무음(-180dB) — 녹음 앱이 노이즈 게이트를 걸었다**. 2번은 -60dB | -57 ~ -60dB |
| 잡음 종류 | 2번: 저역 웅웅거림 우세 | **저역(120Hz 밑) 웅웅거림이 가장 큼**, 중역 방 잡음 다음 |
| 대본 | 송이·송강이 **같은 대본**("안녕하세요 요리 드립입니다…")을 읽었다 | |

노이즈 게이트는 말끝·숨이 잘려 나가고 잡음이 켜졌다 꺼졌다 하는 소리를 만든다. 모델이 이걸 배우면 문장 끝이 뚝 끊긴다. 정제 단계에서 게이트 경계를 찾아 그 근처를 학습 클립 경계로 쓰지 않는다.

## 3. 데이터 정제

녹음 원본은 절대 덮어쓰지 않고, 정제 결과는 비공개 목소리 묶음(`OPENCUT-voices`)과 로컬에만 둔다. 공개 저장소(OPENCUT)에는 오디오도 받아쓴 글도 넣지 않는다.

1. **디코딩**: 48kHz(송이는 44.1k 그대로) 모노 float32. 송이 스테레오는 두 채널이 같은지 먼저 본다(다르면 더 깨끗한 쪽 하나).
2. **저역 정리**: highpass 60–70Hz. 험이 50/60Hz 배음으로 보이면 노치를 더한다. 송강 잡음의 대부분이 여기라 이것만으로 많이 준다.
3. **잡음 제거 후보 비교** (같은 1분 구간에 각각 약·중 두 세기):
   - DeepFilterNet3 (가볍고 빠름, 48k)
   - ClearerVoice-Studio MossFormer2_SE_48K
   - 송강만: 지금 쓰는 UVR5 DeEcho-DeReverb (방 울림이 남아 있으면)
   - 비교 지표: DNSMOS(SIG·BAK·OVRL), 원본 대비 화자 유사도 하락, 4kHz 위 에너지 손실, 그리고 귀로. **잡음 제거는 화자 특징도 깎는다**(연구 결과 일관됨) — 배경 잡음이 들리지 않는 가장 약한 설정을 고른다. 1세대 송강이 울림을 통째로 배운 것처럼, 처리 흔적도 모델이 배운다.
4. **음량**: 학습용은 -23 LUFS로 맞추고 피크 -1dBTP. (최종 출력 -16 LUFS는 지금처럼 후처리에서.)
5. **자르기**: Silero VAD + 받아쓰기 타임스탬프로 문장 경계에서 3–15초 클립. 노이즈 게이트 경계(송이 1·3번), 웃음·말 더듬음·재녹음 구간은 뺀다. 화자당 약 120–160개 클립이 나올 것이다.
6. **받아쓰기**: 대본 원문이 있으면 그것을 정답으로 클립에 맞춰 붙인다(가장 정확). 없으면 Whisper large-v3 계열(MLX, M1 GPU)로 받아 적고 **사람이 한 번 검수**한다. 받아쓰기 오류는 그대로 발음 오류로 학습된다 — 1세대 발음 문제의 숨은 원인일 수 있다. 검수는 클립을 듣고 글자를 고치는 간단한 로컬 화면으로 한다(화자당 20~30분 예상).
7. **홀드아웃**: 화자당 약 1분(10~15클립)은 학습에서 빼 평가용 정답으로 둔다. 같은 문장을 합성해 실제 녹음과 1:1로 비교할 수 있다.
8. **예전 학습 데이터**: 1-1 결과상 지금 목소리와 달라 **기본은 쓰지 않는다**. 새 데이터 22분으로 부족하면 예전 데이터 중 새 녹음과 유사도 높은 클립만 추가해 본다(P3 실험 하나).

### 4-3. 진행

1. **1차 (제로샷, 하루)**: 학습 없이 정제한 참조 클립(10–20초)만으로 네 후보를 평가 묶음에 돌린다. 발음과 M1 속도·메모리가 여기서 갈린다. 상위 2개를 고른다.

3. **최종**: 사용자 블라인드 청취로 정한다.

## 5. 속도 1.2와 피치

원칙: **속도는 모델이 직접 빠르게 말하게 하고, 다 만든 소리를 늘이거나 줄이지 않는다.** 1세대에서 soundtouch로 줄였더니 CER이 0.17 → 0.31로 나빠졌다(2026-11-15). 지금 GPT-SoVITS의 토큰 솎기도 같은 문제를 안고 있다(1-3).

속도 내는 방법(측정해서 위에서부터 쓴다):

1. **참조·학습 클립의 템포**: LLM형 복제 모델은 참조 음성의 말 빠르기를 따라간다. 홀드아웃 아닌 클립 중 조음 속도 상위 클립을 참조로 고르고, 필요하면 참조만 고품질 시간 줄이기(Rubber Band R3, 포먼트 유지)로 1/1.2 줄여 넣는다. 1세대가 참조를 0.8배로 늦춰 속도를 맞춘 것과 같은 방식의 반대 방향이다.
2. **모델 고유 조절**: 후보가 속도 지시나 길이 조절을 지원하면 그것을 쓴다(CosyVoice3 지시문 등).
3. **쉼 줄이기**: 문장 앞뒤 무음(`TTS_WEB_LEAD_MAX`·`TAIL_MAX`)과 문장 안 쉼을 줄인다. 체감 속도가 오르고 음높이·발음에는 영향이 없다.
4. **마지막 수단**: 1~3으로 모자란 몫(1.05배 이하)만 Rubber Band R3로 줄인다. CER이 나빠지지 않는지 평가 묶음으로 확인한 경우에만.

피치 지키기:

- 목소리마다 기준 음높이(새 녹음 F0 중앙값: 송이 약 216Hz, 송강 약 115Hz)를 `tts-voices.json`에 둔다.
- 문장마다 F0 중앙값이 기준 ±1반음을 벗어나면 다시 만든다. 지금의 끝 올림 검사(`end_rise`, pyin을 이미 돌린다) 옆에 붙이므로 추가 비용이 거의 없다.
- 송강 +3반음은 검사로 막을 문제가 아니라 데이터 문제다. 새 녹음으로 학습하면 사라지는지 P3에서 확인한다.
- 속도 눈금: 새 시스템의 1.0 = 새 녹음의 자연스러운 속도(약 6.0음절/초)로 정의하고, 기본값 1.2(`tts.env` `TTS_SPEED`, OPENCUT `NARRATION_RATE`는 그대로 1.2). 1-4절대로 지금보다 약 10% 빨라진다 — 10절 질문 3에서 확정한다.

## 7. OPENCUT 연동

웹 앱은 거의 안 고친다. 계약이 그대로라서다.

- `apps/tts/tts-web.py`: `synthesize()`가 목소리 항목의 `engine` 값에 따라 새 엔진 서버(새 포트, 예: 9881)로 보낸다. 문장 나누기(`segments`), 숫자 읽기(`normalize`), 발음·속도·끝 올림 검사, 후처리, 형식 변환은 그대로 쓴다.
- 발음 검사 Whisper를 small → large-v3 계열(MLX)로 올린다. small은 "큰 실패"만 잡도록 맞춰 둔 것이라 "식혀서→시켜서" 같은 한 글자 오류를 못 잡는다. 메모리·시간은 P5에서 잰다.
- `tts-voices.json`: 목소리마다 `engine`, 가중치 경로, 기준 음높이. `model` 값이 바뀌므로 편집기가 예전 음성을 "예전 모델"로 표시하고, #63의 "목소리만 다시 만들기"로 기존 프로젝트 내레이션을 Claude 사용 없이 새로 만들 수 있다.
- `setup-mac.sh`·`setup.env`·`requirements-mac.txt`·`voices-release.sh`: 새 엔진 설치와 새 목소리 묶음(Release `voices-YYYYMMDD`).
- 말투(밝게·부드럽게)와 프리셋: 새 엔진에서 다시 만든다. 새 녹음엔 말투 클립이 없어 처음엔 "기본" 하나로 시작하고, 필요하면 말투별로 1~2분 더 녹음한다.
- 새 엔진이 합격하면 GPT-SoVITS(12GB, 패치, UVR5, BERT 지연 로딩 등)는 **지운다**. 둘을 계속 들고 가지 않는다.

- 검사 보강: small 은 문장 끝 웅얼거림을 놓쳤다(송강 "이선, 댕어…", 송이 끝에 대본에 없는 문장) → 2세대는 large-v3-turbo(문장당 약 1.5초, large-v3 는 없는 말을 지어내 탈락), 조음 속도 하한 4.5(실제 녹음 하위 1% 4.5–4.8, 웅얼거림 붙은 것 4.7). 끝 올림 검사는 실제 녹음에서 4반음 넘는 평서문이 송이 4/33·송강 1/33 → 송이만 6.
- 실측 (대본 1의 11문장 + 1문장, 298자, 편집기 1.2): 송이 46초 소리에 60초, 송강 41초에 54초 (1세대 송이 2.2배·송강 4.2배). large-v3-turbo 로 다시 받아 적어 한 글자("조절→저절") 외 일치.
- 숫자 읽기: "공기"를 고유어 단위에 추가 (2공기 → 두 공기).
